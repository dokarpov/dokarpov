## What I actually do

I work on the layer between strategy and execution.

I’m usually brought into problems where the interface is not the real problem.

The real problem is somewhere underneath:

- fragmented sources of truth
- manual operational decisions
- weak product logic
- unclear ownership
- expensive exceptions
- ambiguity that breaks automation
- teams shipping features without changing the underlying system

My work is to turn that mess into a product model that can actually operate.

**I map the decision system, redesign the logic, define the experiment and build the first working version.**

`messy operation → decision model → product logic → prototype → evidence → scale`

## How I think

A better interface does not fix a broken mechanism.

Some of the most expensive product problems are not UI problems at all.  
They are problems of state, ownership, confidence, logic and actionability.

That is usually where I work.
